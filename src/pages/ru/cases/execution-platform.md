# Распределённая платформа исполнения ML-нагрузок

### 🛠️ Обзор инфраструктуры
Асинхронная система исполнения долгих и ресурсоёмких задач машинного обучения (обучение/инференс YOLOv8 и мультимодальных моделей Qwen2.5-VL) без блокировки клиентского API. Архитектура разделяет приём HTTP-запросов, постановку задач в очереди и вычисления на GPU-воркерах с оптимизацией видеопамяти.

- **Репозиторий исходного кода:** [ml-workload-execution-platform](https://github.com/ajdanoff/ml-workload-execution-platform)
- **Ключевой стек:** FastAPI // RabbitMQ // Celery // vLLM // AWQ и 4-bit NF4 квантование // Pydantic v2

---

## 🏗️ Асинхронная маршрутизация задач и архитектура брокера

Платформа устраняет классическую уязвимость Python ASGI-сервисов, при которой тяжёлые матричные вычисления выполняются в потоке HTTP-сервера и блокируют `asyncio` Event Loop.

```text
[ HTTP POST запрос ] ──► FastAPI Router
                             │
                             ▼ (Мгновенный ответ 202 Accepted + task_id)
                      [ RabbitMQ Exchange ]
                             │
            ┌────────────────┴────────────────┐
            ▼ (Routing Key: workloads.heavy)   ▼ (Routing Key: workloads.light)
     [ Очередь GPU-задач ]            [ Очередь CPU-задач ]
            │                                 │
            ▼                                 ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ Изолированный Celery GPU     │   │ Изолированный Celery CPU     │
│ └── vLLM Server (Qwen2.5-VL) │   │ └── Аудит данных и метрик    │
└──────────────────────────────┘   └──────────────────────────────┘
```

### 1. Жизненный цикл долгих операций (Long-Running Operations)
* **Валидация контракта:** при поступлении запроса `POST /api/v1/workload/run` схема данных мгновенно проверяется через **Pydantic v2** до постановки в очередь.
* **Неблокирующий ответ:** API публикует сообщение в **RabbitMQ**, возвращает клиенту `202 Accepted` с уникальным `task_id`, а изолированные воркеры **Celery** забирают задачу по мере освобождения GPU.

### 2. Защита от дублирования (Идемпотентность)
Для предотвращения повторного запуска дорогих GPU-задач при сетевых ретраях клиента реализована проверка ключа идемпотентности (`X-Idempotency-Key`) через атомарные блокировки в in-memory хранилище: конкурентные дубликаты отклоняются со статусом `409 Conflict`.

## 💾 Оптимизация видеопамяти: инференс 7B VLM в 16 ГБ VRAM

Запуск **Qwen2.5-VL-7B-Instruct** в нативной точности FP16 требует ~15–16 ГБ VRAM только под веса модели. Для стабильной работы на видеокартах уровня NVIDIA T4 (16 ГБ) реализована следующая конфигурация:

* **vLLM Runtime:** использование PagedAttention для устранения фрагментации памяти KV-кэша.
* **Квантование AWQ (Activation-Aware Weight Quantization):** сжатие весов до 4 бит с защитой критически важных каналов активаций уменьшает объём модели в **~3.5 раза** (~4.5–5 ГБ), оставляя запас памяти под визуальные эмбеддинги и батчинг без потерь точности координат bounding boxes.

## 🛡️ Четырёхуровневая матрица качества (Quality Gates)

1. **Fast CI:** изолированные контрактные тесты схем Pydantic и граничных значений в рамках каждого PR.
2. **Nightly Integration:** поднятие связки **FastAPI + PostgreSQL + RabbitMQ** в Docker Compose и проверка сквозного прохождения задач.
3. **Fault Injection:** эмуляция падения воркеров, обрыва связи с БД и брокером с проверкой маршрутизации сбойных задач в Dead Letter Queue (DLQ).
4. **Performance Gates:** нагрузочное тестирование и контроль процентилей `p95`/`p99` latency перед релизом.
